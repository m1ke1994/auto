# TrackNode Studio 2.0 — local MVP slice

This branch does not deploy production. Demo uses deterministic escaped static HTML, not AI.
Existing accounts/JWT are reused. Each project and revision is owner-scoped.
Local approval records a revision only; it does not host a site. ZIP contains portable HTML.

## Local Docker
From ydro:
```sh
docker compose -p tracknode20 -f docker-compose.yml -f docker-compose.studio.yml up --build -d postgres redis backend frontend
docker compose -p tracknode20 -f docker-compose.yml -f docker-compose.studio.yml exec backend python manage.py migrate
docker compose -p tracknode20 -f docker-compose.yml -f docker-compose.studio.yml exec backend python manage.py test ai_builder
```
Open http://localhost:8001/studio and sign in/register. Stop using compose down (never -v).
Use a separate checkout and ensure ports 8000/8001 are free. No production credentials.
For native Django set STUDIO_DEMO_ENABLED=1 and SQLITE_NAME=studio-local.sqlite3, migrate and run.

## Windows startup / troubleshooting

From the ydro directory run:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-studio.ps1
```
Use `-SkipBuild` to reuse the current images, or `-Test` to run Studio tests after startup. The script uses the existing tracknode20 project and database volumes, optionally reads .env.studio.local, validates Compose, builds images, waits for the HTTP healthcheck, checks Django and prints migration status. Failure prints service logs and healthcheck output. No destructive cleanup is performed.

Dockerfile.studio is separate from production Dockerfile.backend. It normalizes the entrypoint inside the image, checks shell and Python syntax, installs dependencies from official PyPI, and checks package consistency. Studio health checks target localhost inside the backend container, allow time for real migrations, and do not conceal failed application startup. The local override disables example site seeding. Docker Desktop with Compose supporting --wait is required.

If a previous local Git patch conflicts during pull, keep a backup and resolve the conflicting files before building. Do not delete database volumes or run git reset --hard. A successful build alone does not guarantee that migrations or runtime checks pass. Inspect logs if any check fails.

## Poly Haven 3D models

## Premium asset selection and camera framing v2
Metadata-based rankings replace ascending polygon counts for both providers. Realistic mode rejects explicit toy/cartoon/low-poly indicators and extremely sparse vehicle meshes; explicitly selected stylized mode allows stylized assets. Search results carry metadata_score and visual_verified=false, not an artistic score. --check-asset-search 'realistic sports car' tests Sketchfab search without an LLM or model download. Camera fit solves perspective projection of normalized bounding box corners, with constrained opening zoom, oblique opening angles for elongated subjects, directional shadows on optional ground plane, and projected coverage telemetry. Playwright checks hero stage size and approximate projected bounds on desktop/mobile, and samples camera motion within the hero. Bounds do not measure actual rendered pixels or guarantee realism. Existing asset byte/polygon limits unchanged. Real visual critique and mesh simplification remain separate work.

## DeepSeek Flash visual critic
The default studio-quality.ps1 pipeline now runs a separate image-based critic after successful browser QA. It sends only the generated website screenshots and brief to the fixed DeepSeek API endpoint using STUDIO_AI_KEY (no additional provider, no source or other files). Use -SkipVisualReview to opt out. For an existing run, invoke studio-visual-review.ps1 -RunDirectory <run> -Prompt <brief>; no generation or rebuild of the site. Two bounded requests (desktop/mobile), no automatic retry, 4500 output tokens each, 360-second watchdog. Screenshots include five scroll samples per device and, for newer audits, five individual section screenshots. The critic must return structured observations for every screenshot, scores and actionable issues. Each device must score at least 85/100, asset score at least 18/25, composition at least 15/20, and no critical defects. Technical audit must also pass. Reports are preserved in separate visual-review directories. Unavailable/invalid responses never pass. This is subjective AI review of sampled still images, not a human acceptance test, actual motion analysis, pre-download model review, or automatic source repair. No other API credentials or models are required. Actual usage depends on DeepSeek billing. Do not send private client screenshots without permission.

## Targeted repair loop
Use studio-repair.ps1 -RunDirectory <original> -ReviewFile <rejected visual-review.json> -Prompt <original brief> -MaxRepairs 1. Each repair restores only bounded generated sources and credited local assets from the original TrackNode ZIP; trusted runtime files are regenerated. Old versions are not modified. The agent reads existing files, consumes bounded critic notes as untrusted evidence, locks model search/downloads during repair, and checks stale/unused references. An explicitly started attempt has the $2.50 estimated OpenHands budget and 900-second watchdog; two visual review requests per successful build. There is no automatic publication. The loop stops on visual acceptance, unavailable reviewer, technical failure, or attempt limit. New Studio generation uses MaxRepairs 0 and MaxTechnicalRepairs 0, so paid retries never start automatically. Critic instructions preserve demo contact honesty and mandatory attribution.

Python searches at most two queries, up to four Sketchfab details each, attempts at most two downloads; each candidate is exported to a trusted preview site and rendered offline at three fixed angles. One batched Flash visual review accepts only score >=85 with no critical defect. Required models block generation if no candidate passes; optional assets may fall back to editorial. The standalone studio-preflight.ps1 does not call V4 Pro. Reuse successful folder with studio-quality.ps1 -PreflightDirectory <folder> and identical brief/profile/style; the selected local asset is restored and model search/download/remove tools are locked. Full-page visual review still applies. Automatic repairs opt-in at most one; low asset scores stop repair before agent calls. No persistent shared asset library, exact cost cap or guarantee of realism yet. Preflight artifacts and licenses are preserved locally. Only the brief and candidate renders are sent to DeepSeek by preflight. Source and browser verification are independent.

Preflight plan parsing now normalizes harmless formatting variations and logs safe validation reasons. Resume an existing preflight without paying for a new design plan or downloading models: studio-preflight.ps1 -ResumeDirectory <previous preflight folder>. Add -RenderOnly for zero model API calls; without it the visual critic runs only if real frames exist. ## Sketchfab thumbnail screening
Preflight now searches both planned queries (up to six model-detail requests per query). It reviews up to eight verified candidates' public catalog thumbnails in one bounded Flash request, without forwarding Sketchfab credentials. Only thumbnails with score >=75 and no critical defect are shortlisted (two download attempts maximum). Actual local three-angle renders still require >=85 and no critical defect. Thumbnail absence or rejection cannot be bypassed by the developer agent. Use -ExcludeModelId with previous rejected candidate IDs to avoid repeating them; no persistent global blacklist yet. Poly Haven remains on metadata and final rendered review. Planner can be bypassed using manual queries as before.

Candidate handling is now deterministic across Windows PowerShell 5.1 and Python: directory names are derived from manifest order (`candidate-1`, `candidate-2`), not compared against JSON properties. PowerShell verifies each expected ZIP exists before extraction; Python applies the same canonical mapping before visual selection. This removes the brittle `-notin` folder check and prevents manifest paths from being used as filesystem paths.

Windows PowerShell 5.1 emits top-level ConvertFrom-Json arrays differently from newer versions. Preflight now parses the array inside an object, validates the fixed folder names, emits scalar folder names, and runs zero/one/two/invalid manifest regression checks before any Docker or paid API call. `studio-preflight.ps1 -SelfTest` runs only these checks. Both resume entry points share one implementation. Use the original folder containing all candidate archives if a previous resume lost a candidate. Asset review evaluates isolated geometry and materials without penalizing the neutral preview background or adjustable camera distance; the >=85/no-critical gate is unchanged.

## Explicit conditional asset approval
The strict automatic visual gate remains >=85 with no critical defect. When all candidates fail only the premium threshold, `studio-preflight-promote.ps1 -RunDirectory <existing run>` can explicitly promote the highest already-reviewed candidate scoring >=75 with `critical=false`, but only if its ZIP, trusted three-angle render report, diagnostics and screenshots are intact. This path makes no model search, download, render, or DeepSeek request. The selected asset is labeled `quality_tier=conditional` with its critic warning preserved. The generator is instructed not to call it photorealistic and to use deliberate studio presentation. Scores below 75 and all critical rejections remain blocked. Runner accepts premium >=85 or conditional 75-84 only.
