# TrackNode — юридический выпуск для плательщика НПД

Актуально на 15.10.2026. Это проверочный список, а не заключение российского юриста и не гарантия отсутствия штрафов.

## Страницы

- `/privacy` — политика обработки персональных данных.
- `/consent` — самостоятельный текст согласия для публичной формы заявки, без маркетингового согласия.
- `/cookies` — условия использования необходимых настроек и аналитических cookies, способы отзыва разрешения.
- `/terms` — условия использования платформы, статус исполнителя НПД, согласование платных работ, чек «Мой налог», возвраты и законные пределы ответственности.

## Обязательное заполнение перед полноценным юридическим выпуском

1. Укажите реальные ФИО оператора и исполнителя: `VITE_LEGAL_OPERATOR_NAME`.
2. Укажите ИНН физического лица: `VITE_LEGAL_OPERATOR_IDENTIFIER`.
3. Укажите действующий адрес электронной почты для юридических обращений: `VITE_LEGAL_CONTACT_EMAIL`.
4. При необходимости добавьте почтовый адрес для корреспонденции: `VITE_LEGAL_OPERATOR_ADDRESS`. Не публикуйте адрес проживания без необходимости или согласованного решения.
5. Убедитесь, что переменные доступны на **этапе Vite build** через production `vue-admin/.env`, а не только runtime environment; после изменения выполните новую сборку и проверьте опубликованную страницу `/privacy`.
6. Проверьте реальные процессы обработки: способы хранения, категории сведений, сроки, доступы, резервные копии, удаление/отзыв согласия, договоры с обработчиками, конфигурацию учёта cookies и трекеров на всех страницах и клиентских сайтах.
7. Установите применимость уведомления Роскомнадзора по ст. 22 152-ФЗ; при необходимости подайте его и поддерживайте актуальность. **Публикация документов не заменяет уведомление.**
8. Убедитесь в выполнении требований о локализации баз персональных данных граждан РФ (ч. 5 ст. 18 152-ФЗ), о безопасности, реагировании на инциденты и действительном исполнении сроков удаления.
9. Проверьте отдельное согласие при каждой форме и сохранение подтверждения согласия в БД. Публичная форма добавляет в JSON поля `consent_document`, `consent_document_version` и `consent_at`; сохранение метаданных сервером надо проверить отдельно.
10. Если выставляются счета/принимаются платежи, оформляйте чек через «Мой налог» по каждому поступлению и передавайте его заказчику в установленные сроки. Стоимость, период подписки, автопродление, способы отмены, возвраты, предмет и акцепт должны соответствовать реальной платёжной схеме.
11. Сверьте публичные обещания, тарифы и демоданные с реальной функциональностью; не обещайте доход, рост SEO или неограниченное отсутствие сбоев.
12. Отдельно согласуйте политику и договорные условия с юристом, специализирующимся на 152-ФЗ, публичных SaaS и правах потребителей РФ.

## Технический регресс и сохранность данных

- Не менять Django-модели, миграции, PostgreSQL и API заявок ради юридического оформления страниц.
- Перед деплоем сохранить бэкап PostgreSQL. Не выполнять `docker compose down -v`, `docker volume prune`, команды сброса БД.
- Проверить `npm run test:tracknode-landing`, `npm run build:local` и GitHub Actions.
- Проверить в production `/privacy`, `/consent`, `/cookies`, `/terms`, форму заявки и факт отсутствия трекера до выбора аналитики.
- После автодеплоя подтвердить Git SHA, health контейнеров, HTTPS и неизменность пользовательских данных.
